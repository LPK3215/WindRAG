Project Overview

WindRAG answers wind-turbine operations and maintenance questions by retrieving from a domain knowledge base. It is deliberately simple: the entire mainline runs on the Python standard library only — no vector database, no graph database, no training framework — yet it does the basics properly, with traceable sources and honest evaluation.

What it is

  • Conversational retrieval QA (ask / chat)
  • Zero-dependency web page rendering results + sources
  • Keyword + sparse-semantic + rule-fusion rerank
  • Optional LLM via stdlib urllib
  • Import your own docs (txt/md/json/csv/docx)

What it is not

  • Dense-vector semantic search (substituted by TF-IDF)
  • Heavy front-end framework (native HTML/CSS/JS, no CDN)
  • Neural retrieval model / training pipeline
  • A required LLM (extractive answers work without one)
  • Online crawling / data pipelines

Core Method

Adaptive-alpha hybrid fusion

Shybrid(q,d) = α · ̂Svec(q,d) + (1−α) · ̂SBM25(q,d)

α is predicted from query features (standard-number / numeric / term-dense / maintenance / fault / performance / principle), optionally fixed via tune. Ablation shows a fixed low α (≈0.3) beats the adaptive predictor on the large corpus.

Retrieval

  • BM25: IDF(t)·tf·(k1+1) / (tf + k1·(1−b+b·|d|/avgdl))
  • TF-IDF: sublinear tf, smoothed IDF, L2-normalized cosine
  • RRF multi-list merge, MMR reranking (diversity vs. relevance)

Refusal gate (before generation)

  • Coverage = IDF-weighted query-term coverage in retrieved docs (blocks out-of-domain)
  • Knowledge-graph combination check on component×fault (blocks pseudo-questions whose terms exist but the pair does not)
  • Weak hits are refused and no LLM call is made

Generation

  • Extractive: sentence scoring by query-term IDF + structure-label bonus + near-duplicate filter
  • Optional LLM (stdlib urllib) with free-tier model pool; on failure it returns to extractive and sets llm_error

Quick Start

No pip install, no model required. Works in a clean Python 3.10+ interpreter.

bash
# build the index (tokenize + BM25 + TF-IDF + new-word discovery)
python src/rag_cli.py build
python src/rag_cli.py ask "gearbox overheating handling" --show-docs
python src/rag_cli.py chat                # interactive multi-turn QA
python src/rag_cli.py serve --port 8000   # open http://127.0.0.1:8000

A Makefile wraps the same commands (make build, make serve, make eval-report, ...).

Retrieval and generation are separate: without LLM_API_KEY (or with DISABLE_LLM=true) retrieval still returns documents and generation falls back to an extractive answer — it never errors or hangs.

Library & API

python
import sys; sys.path.insert(0, "src")
from pure_rag import RAGEngine

engine = RAGEngine(use_llm=False)
result = engine.query("gearbox overheating handling?")
print(result["answer"])
for doc in result["retrieved_docs"]:
    print(doc["score"], doc["matched"], doc["metadata"]["title"])
