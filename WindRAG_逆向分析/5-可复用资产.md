# 5. 可复用资产

以下思路/模式/代码可迁移到通用 RAG 项目（结合"关注的核心问题：垂直领域 RAG 的检索质量与鲁棒性"）。

---

## 5.1 模式：规则先验 + 轻量模型残差（★最高价值）

- **来源**：`adaptive_fusion.py:65-135`。
- **适用**：任何"需要自适应超参、但样本少、要可解释"的场景（不止融合权重，还可用于 rerank 阈值、top-k 动态选择）。
- **迁移方式**：先写可解释规则产出 baseline 值，再用小 MLP/线性回归学残差，推理时相加并 clip。比直接端到端学更稳、可 debug。

## 5.2 模式：三路检索互补 + 统一融合接口

- **来源**：`run_rag.py:182-238`。
- **适用**：垂直领域同时含"标准编号/参数(需BM25)"与"口语描述(需向量)"的混合查询。
- **迁移方式**：把 `retrieve_documents` 抽象成 `retriever` 注册表，各路实现统一 `retrieve(query, k)->List[(doc,score)]`，由 fusion 模块组合。比把各路写死在门面里更易扩展第四路（如 SQL/API 检索）。

## 5.3 模式：线程安全模型池 + 优雅降级

- **来源**：`model_manager.py:15-135` + `run_rag.py:370`。
- **适用**：多模型供应商/多密钥、需高可用的生成层。
- **迁移方式**：`get_response()` 的"遍历+锁+try_next+None降级"可直接套用；建议补：异常分类（429/401/timeout）与退避；模板降级作为兜底。

## 5.4 模式：垂直领域配置单例（DomainConfig）

- **来源**：`run_rag.py:37-92`。
- **适用**：把"行业词典/标准号/组件树"集中管理，供特征、切分、模板答案共用。
- **迁移方式**：用 dataclass 承载领域先验，避免把领域知识散落在多处 if-else。

## 5.5 模式：合成数据自洽闭环

- **来源**：`generate_training_data.py` → `train_adaptive_fusion.py` → `build_index.py` → `evaluation.py`/`ablation_experiment.py`。
- **适用**：教学、论文复现、冷启动无标注时。
- **注意**：⚠️ 合成标签只能证明"方法不出错"，不能证明"优于人工策略"，生产前必须用真实标注校准。

## 5.6 可直接借用的代码片段

| 片段 | 位置 | 用途 |
|------|------|------|
| `split_into_chunks()` 句级切分 | data_processing.py:175-224 | 中文文档切分基线 |
| `construct_knowledge_graph()` 三元组建图 | knowledge_graph.py:11-160 | 轻量图谱构建模板 |
| `_rerank_documents()` 余弦重排 | run_rag.py:258-278 | 快速重排基线（建议换 cross-encoder） |
| `_generate_template_answer()` 模板兜底 | run_rag.py:370-420 | 无 LLM 时的可用降级 |

---

## 5.7 不建议直接复用的部分

- `ablation_experiment.py` 的 WDS 指标（query-doc 同源余弦，自相关偏倚）。
- `_rerank_documents` 作为"伪重排"——若无 cross-encoder，可省略此步直接按融合分排序，省一次编码。
- `config.env` + `sys.path.append('.')` 的全局路径耦合——生产应改用包安装 + 配置中心。
